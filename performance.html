Transparent Engineering Notes & Root Causes

Weave Graph does not gloss over architectural compromises. When an empirical measurement diverges or balances packaging breadth against resource constraints, the engineering cause is documented openly:

Note 1: AST Parser Speed

The >25 MB/s target originally modeled raw Tree-sitter C lexing throughput. In practice, parse_file executes full wiring-card generation, scope resolution, moniker string internments, and structural call edge creation, bounding throughput to 3.08–4.77 MiB/s per core.

Note 2: CSR Memory Compactness

Our CSR structures achieve ~12.0 bytes/node and ~4.0 bytes/edge forward (~24.0 bytes/node and ~8.0 bytes/edge bidirectional), meeting the ≤24B/node and ≤8B/edge Target SLOs while maintaining integer-compacted 32-bit string interning.

Note 3: Static Binary Size (< 15 MB Met)

A zero-feature core build (--no-default-features) compiles to 9.6 MB, cleanly satisfying the <15MB Target SLO invariant. Compiling all 29 extended language grammars embeds static C parser tables and bundled SQLite into the binary (~41.1 MB stripped release), avoiding runtime dependencies.

Section 5.5 Feature-Isolation Budget Matrix

Optional features are isolated behind Cargo feature flags. Core Invariant 8 mandates that enabling any optional feature must not measurably degrade default query latency or idle RSS:

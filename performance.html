Transparent Engineering Notes & Root Causes

Weave Graph does not gloss over architectural compromises. When an empirical measurement diverges or balances packaging breadth against resource constraints, the engineering cause is documented openly:

Note 1: AST Parser Speed

The >25 MB/s target originally modeled raw Tree-sitter lexing throughput. In practice, parse_file executes full wiring-card generation, scope resolution, moniker string internments, and structural call edge creation, which bounds execution to ~4 MiB/s per core.

Note 2: CSR Edge Width

Our CSR edges store an f64 traversal weight (8 bytes) alongside a 4-byte column index (uint32), totaling 12 bytes. Meeting the ≤8-byte SLO would require dropping weights or shrinking to f32, which would compromise weighted call graph traversal.

Note 3: Static Binary Size (< 15 MB Met)

A zero-feature core build (--no-default-features) compiles to 9.6 MB (or 13.8 MB core CLI), cleanly satisfying the <15MB Target SLO invariant. Compiling all 29 extended language grammars statically embeds 29 C parser tables and bundled SQLite into the binary (~41.1 MB stripped release), avoiding runtime Node/Python dependencies.

Section 5.5 Feature-Isolation Budget Matrix

Optional features are isolated behind Cargo feature flags. Core Invariant 8 mandates that enabling any optional feature must not measurably degrade default query latency or idle RSS:

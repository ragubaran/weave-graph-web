Development Roadmap

Continuous Evolution

Explore the phased architecture of Weave Graph — from foundational single-repo deterministic speed to multi-repo federation, team collaboration, and local model routing.

Phase 1 — Core Engine Foundation Completed & Shipped (v1.0.0)

Deterministic Core, SQLite & Local MCP Server

Deterministic engine with a <15MB core-only binary (--no-default-features), integer-compacted CSR graph model, SQLite persistence, and a native MCP server for AI coding agents. A <80MB RAM target at 500k symbols is tracked on the Performance page — the storage+CSR layer alone measures well under that; full-pipeline indexing is still being brought under it.

  • Zero-LLM AST Parsing (29 Languages): High-throughput Tree-sitter parsers for Rust, TS/JS, Python, Go, Java, C/C++, C#, Kotlin, Swift, and more with relative SCIP monikers.
  • Integer-Compacted CSR Matrix: Contiguous uint32 adjacency matrices (petgraph::csr) with Roaring bitmap set-intersections for microsecond-scale traversals (~30µs for a 3-hop query).
  • Crash-Resilient Indexing & Purge: Atomic .rebuild swap and mandatory bidirectional edge purging preventing dangling pointers.
  • Native MCP Server: Stdio and loopback HTTP MCP server (weave serve --mcp) with live reload on external reindex.
  • PR Blast Radius Analysis: Git three-dot diff traversal (weave blast) with markdown and JSON export formats.
  • Strict Quality Standards: ≥90% line coverage on the default-feature build, Google Rust style, and forward beta-compiler compatibility.
Phase 2 — Federation & Team Intelligence Done (unreleased)

Multi-Repo Federation, Contract Drift & Developer Ergonomics

Cross-repository graph composition, boundary contracts, markdown/Obsidian knowledge graphs, debounced watch mode, and local NL intent routing. Built on top of v1.0.0; not yet tagged as a release — see Release Notes.

  • Zero-Config MCP Setup & Smart Ignore Management: weave init auto-registers .mcp.json for clients that read it, and manages .gitignore/.ignore so the derived graph database stays untracked while config.toml stays tracked.
  • Federation Virtual Schema (feature: federation): Multi-repo linking (weave link <a> <b>, exactly two repos), persisted cross-boundary queries (weave query-federated), and unified canvas maps.
  • Topological Cycle Analysis & Contracts: Tarjan's Strongly Connected Components (SCC) and automated public API contract drift CI gates (weave check-contracts).
  • Markdown & Obsidian Ingestion (feature: docs): Streaming markdown parser (pulldown-cmark), wikilinks, and .canvas export.
  • Pinned Symbol Notes (feature: notes): Persistent agent/human knowledge pins (weave note pin / weave note list, MCP recall) with content-hash staleness tracking.
  • Debounced Watch Mode & HTML Viewer: File watcher (feature: watch) with blast-radius gating and an offline HTML viewer (feature: viz, weave report --html / weave viz).
  • Snapshot Hub Client (feature: hub): Snapshot hydration and delta publishing (weave sync pull / weave sync push) against a self-hosted weave-registry server.
  • Local SLM Query Intent Router (feature: slm, experimental): Deterministic and on-device GGUF intent routing (weave ask, weave journal).
  • Pluggable Storage & Python Bindings: A library-only libSQL/Turso storage backend (feature: turso, no CLI selector yet) and standalone PyO3 query bindings (feature: python).
Phase 3 — Self-Hosted Scale & Custom Extensions Done (unreleased)

Query-Layer RBAC, Hybrid Search, SCIM & Self-Hosted Registry

Self-hosted security controls, trace overlays, architectural boundary enforcement, snapshot provenance, and an experimental vector search path, all isolated behind Cargo feature flags.

  • Query-Layer RBAC (feature: rbac): Storage/traversal boundary node masking with identity enforcement (--as, --require-as), per-user path_scope, and SCIM 2.0 directory synchronization.
  • Architectural Policy Linter (feature: policy-lint): YAML boundary rule verification (weave policy lint) and architectural drift analytics (weave policy drift).
  • Hybrid Search: FTS5 BM25 keyword search over name, signature, body, and doc comment (feature: fts) and an experimental mock-embedding vector path (feature: vector, sqlite-vec) — not yet a trained-model semantic search.
  • OpenTelemetry Trace Import (feature: otel): Importing a JSON trace export (weave traces import) to overlay latency percentiles on graph nodes.
  • Snapshot Provenance (feature: hub-provenance): HMAC-SHA-256 snapshot signing and verification, keyed by an operator-held secret, before registry ingestion.
  • In-Browser WASM Graph Runtime (experimental): Standalone 155.6 KB weave-graph-wasm crate for client-side offline graph traversal — not yet a Cargo feature or part of any release build.
  • Self-Hosted Registry Service: Chunked upload spooling and bearer-token-authenticated registry backend (weave-registry).
  • Drift Waivers: Role-gated drift waivers (--allow-drift) and audited PR blast exemptions (--skip --reason).
  • PR Review Risk Scoring (feature: pr-review): weave pr-review reuses weave blast's own diff/traversal for a deterministic, fixed-threshold risk header (no model), then aggregates contract drift, policy lint violations, and weave verify's phantom-symbol check into one severity-ranked findings list (blocker/warning/info, mapped to GitHub's own Checks API annotation levels), with --waive/--fail-on and a documented stable --format json contract for external LLM reviewers. --stack-base <ref>|auto scores a stacked branch's own diff apart from the cumulative diff to its merge target, and --lane <ref> (repeatable) scores parallel refs independently alongside the main report — both plain git refs, no third-party git client's on-disk format involved.
Phase 4 — Developer Performance, Evidence-Based Review & CI Gates Partial — Release Gates Open

Measured Profile Baselines, Review Evidence & Resource Budgets

Deterministic developer-performance and evidence-based review work, no model, no network. Several items are code-complete with their size/RSS/latency measurement explicitly held, not claimed — this phase's release gates remain open pending that measurement, mainly on Linux.

  • Profile Truth & CI Gates: Reproducible release-build measurements across every profile (core, basic, extended-language, vector, slm) and a CI check rejecting network/model-downloader dependencies from the core build. Full-pipeline indexing RSS and p50/p95 reindex latency baselines remain held pending measurement.
  • Bounded Indexing & Graph Integrity: Fixed ordered parse batches, a deterministic 500k-symbol indexing harness (pipeline_rss.sh), and atomic staged-database promotion. Linux-specific RSS verification is still open (measured on macOS so far).
  • Review Evidence (weave blast): Bounded, deterministic changed-file impact evidence — touched symbols, callers/callees, exported contract surface — feeding directly into PR review.
  • Optional Response Compression: Opt-in gzip negotiation for MCP HTTP and Hub snapshot transport (feature: http-compression), disabled below a measured size crossover, stdio unaffected.
Phase 5 — Explicit On-Demand Local Assistant (SLM) & Held Model-Backed Work Held

Generative On-Device Assistant & Vision Ingestion

Model-backed work, deliberately tracked apart from the deterministic core so none of it ships enabled by default. Not started.

  • Real generative on-device assistant: A model-backed weave ask beyond the deterministic intent router Phase 2 already ships. Not started.
  • Vision ingestion: Scanning images and diagrams with a local GGUF vision model. Not started, held on the same model-backed criteria as the assistant above.
Phase 6 — Turso Backend Selector Held

libSQL/Turso as a CLI-Selectable Storage Backend

The turso feature already exists as a library-only storage backend (Phase 2); making it selectable from the CLI alongside the default rusqlite backend is held pending demand.

  • CLI storage backend selector: No CLI flag to choose Turso over the default backend yet; the library backend itself is wired and tested. Held, not started.
Phase 7 — Search & Storage Tuning (M7.1–M7.11) Done

FTS Body/Doc-Comment Indexing, Fuzzy Resolution & Storage Measurement

10 of 11 planned items implemented and tested; the remaining item is code-complete with its size/RSS measurement explicitly held rather than claimed.

  • FTS body & doc-comment coverage: weave search's BM25 index now covers a symbol's body and doc comment, not just its name and signature.
  • Fuzzy symbol-resolution fallback: A deterministic case-insensitive → short-name → Levenshtein-distance fallback chain, shared between the CLI and MCP resolvers.
  • cache_size investigation: Benchmarked at 500k- and 50M-row scale — a real but modest win at 500k, no consistent win at 50M, so no default changed on unproven benefit.
  • Grep fallback & WAL checkpoint valve: Additional storage-tuning items landed in the same pass.
Phase 8 — Embedding / Vector Search (BGE Semantic Retrieval) Held — Product Decision

Trained-Model Semantic Search (BAAI/bge-small-en-v1.5)

The experimental mock-embedding vector path already ships (Phase 3); swapping in a real trained embedding model is held on a product decision, not started.

  • Trained BGE embedding model: Selected candidate (BAAI/bge-small-en-v1.5), installed explicitly and kept outside the core dependency closure. Not started.
Phase 9 — Skylos-Style Verification & Submodule Contract Checking Done

Pre-Flight Verification (weave verify) & Submodule Contract Drift

All five milestones implemented and tested, feature-gated on the existing rbac/policy-lint/federation/hub/vector tiers — zero change to the default binary.

  • weave verify: Tri-state (pass/fail/incomplete) pre-flight check for phantom symbols, submodule encapsulation violations, and stale submodule references — never a false pass.
  • weave check-contracts --submodules: Per-submodule boundary contract drift, consumer-scoped so a pointer bump with zero parent-repo callers reports informational, not blocking.
  • Declarative contracts: .weave/contracts.yml plus a weave_verify MCP tool.
  • Six deferred-capability fixes: RBAC-scoped policy exemptions, path-scoped identities, policy waivers, opt-in semantic-coupling drift, federated policy lint, and a Hub mesh policy-lint route — each closed independently.
Phase 10 — Competitive Feature Adoption Mostly Done

Budgeted MCP Tools, Edge Provenance & Query Grammar Filters

Recommendations from an internal competitive review; most items done and tested. Two are honestly left partial — a real mechanism shipped, with a benchmark or Linux-verification half needing infrastructure this project doesn't have yet — and one is deliberately not started.

  • weave_explore: One budgeted MCP tool composing repo map, file API, call trace, impact radius, and a source excerpt under one token budget, RBAC-masked before truncation.
  • weave_check_freshness: Always-on MCP tool distinguishing Fresh/Behind/Dirty/Unknown — never a false "fresh."
  • weave_find_all: Exhaustive (not ranked top-N) FTS5 symbol-aware search.
  • Edge provenance & confidence: Every edge now carries an Exact/Heuristic confidence tag, inspectable via weave query's precise: filter.
  • Query grammar filters: path:/lang:/kind:/visibility:/edge: on weave query, fully backward-compatible.
  • Framework route pilot: Flask @app.route decorator detection (feature: framework-routes, off by default), zero default-build cost.
  • Memory-bounded indexing (partial): A cgroup/container-aware admission budget shipped and tested; the Linux RSS-ceiling verification half is still open (this project's sandbox is macOS-only).
  • Not started, by deliberate choice: SCIP/LSP precision import — would need a new protobuf dependency or an unvalidated hand-rolled parser, neither of which clears this project's zero-invention bar yet.
Phase 11 — PR Review Speedup & Deterministic Risk Scoring Done

weave pr-review: Risk-Scored PR Artifact, Stacked Branches & Lanes

All eight milestones implemented and tested; Custom-tier only (feature: pr-review).

  • Deterministic risk score: Fixed-threshold Low/Medium/High/Critical header, reusing weave blast's existing traversal — no model.
  • One consolidated artifact: Aggregates contract drift, policy lint violations, and weave verify's phantom-symbol check into one severity-ranked findings list (blocker/warning/info, mapped to GitHub's own Checks API annotation levels).
  • --waive / --fail-on: An audited bypass mechanism reusing this project's existing waiver pattern; a documented, stable --format json contract for an external LLM reviewer.
  • --stack-base <ref>|auto / --lane <ref>: Stacked-branch-aware and parallel-lane scoring — both plain git refs, no third-party git client's on-disk format involved.
  • Local pre-push pipeline gate: weave hooks install/uninstall wires weave blast and weave check-contracts --submodules into an offline pre-push hook.

Feature Isolation

Optional features (federation, hub, provenance, slm, rbac, turso, policy-lint, pr-review) are compiled in behind Cargo feature flags, verified to add zero new dependency edges to a default build's dependency tree — enabling one is intended not to measurably change default-build query latency or idle memory use.

Getting Started

Build the weave binary, index a repository, connect your coding agent over MCP, and add checks for pushes and pull requests.

1

Install the CLI

Building from source is the only install path today. You need a Rust toolchain; SQLite is bundled, so there is nothing else to install. Package-manager releases and GitHub Release binaries are not published yet — they are planned for v1.0.1, which is still in development. 

# Recommended: the team bundle (docs, federation, fts, vector)
cargo install --git https://github.com/ragubaran/weave-graph.git weave-graph-cli --features team

# Add notes, the file watcher and the HTML viewer (not part of the team bundle)
cargo install --git https://github.com/ragubaran/weave-graph.git weave-graph-cli --features team,notes,watch,viz

# Or clone and build
git clone https://github.com/ragubaran/weave-graph.git
cd weave-graph
cargo build --release -p weave-graph-cli --features team
cp target/release/weave ~/.local/bin/

weave --version

Which features to build
  • --features team: multi-repo linking, contract checks, weave verify, Markdown/Obsidian ingestion, weave search.
  • notes, watch, viz: add them explicitly; neither team nor custom includes them.
  • --features custom: team plus hub sync, snapshot signing, RBAC, trace import and policy lint. See Self-Hosted.
  • Binary size: the default and team builds are about 41 MB. The core-only build (--no-default-features, 8 languages) is about 9.7 MiB. Windows builds are untested.

Initialize and Index a Repository

weave init does three things: writes .weave/config.toml, adds a weave server entry to .mcp.json at the repo root (merging with any servers already there), and updates .gitignore / .ignore so the database stays out of Git while config.toml stays tracked. It is safe to run more than once. 

# 1. Initialize in the project root (single is the default mode)
weave init --mode single

# 2. Build the index
weave index

# 3. Show file, symbol and edge counts, database size and pending markers
weave status

# Later: re-parse only files changed since the last index
weave index --incremental
# 1. Initialize and index each repository on its own
cd ../backend-core && weave init --mode multiple && weave index
cd ../gateway-api  && weave init --mode multiple && weave index

# 2. Link two repositories (feature: federation, in the team bundle).
#    Each repo is added to the other's [federation] linked_repos.
weave link ../backend-core ../gateway-api

# From inside a repo, one path is enough: the current repo is linked to it.
# With no path, the partner is read from [federation] linked_repos.
weave link ../backend-core
# Requires a build with --features custom
weave init --mode single

# Point at your weave-registry and, optionally, move the database off the repo tree
weave config set hub.url "http://hub.internal.corp:8080"
weave config set storage.home "/var/weave-vault"

# Pull the snapshot for the merge-base commit, falling back to the hub's latest,
# or build locally if the hub has none
weave sync pull --fallback-latest || weave index

Connect AI Agents (Claude Code, Cursor, Windsurf)

weave serve --mcp runs a Model Context Protocol server over stdio (default) or loopback HTTP. Clients that read a project-level .mcp.json, such as Claude Code, pick it up after weave init with no further setup. Other clients need their own config entry pointing at weave serve --mcp. 

# weave init already registered the server in .mcp.json.
# To register it yourself instead:
claude mcp add weave -- weave serve --mcp

# Verify registration
claude mcp list
// Add to ~/.cursor/mcp.json or the workspace's .cursor/mcp.json:
{
  "mcpServers": {
    "weave": {
      "command": "weave",
      "args": ["serve", "--mcp"]
    }
  }
}
// Add to ~/.codeium/windsurf/mcp_config.json:
{
  "mcpServers": {
    "weave": {
      "command": "weave",
      "args": ["serve", "--mcp"]
    }
  }
}
# HTTP transport, bound to 127.0.0.1 by default
weave serve --mcp --transport http --port 8080

# Binding beyond loopback needs an explicit opt-in (exposes code structure)
weave serve --mcp --transport http --host 0.0.0.0 --allow-remote

# RBAC builds: refuse to start unless an identity is given
weave serve --mcp --require-as --as alice
MCP tools: 7 core + 5 feature-gated
weave_repo_map — overview of the repository's structure
weave_file_api — compact wiring summary per file
weave_trace_calls — incoming/outgoing call chains up to N hops
weave_impact_radius — blast radius of a proposed change
weave_explore — map, file API, call trace, impact and source excerpt in one token budget
weave_check_freshness — whether the index is behind HEAD or uncommitted edits
weave_verify — checks one file for phantom symbols before an edit is presented
weave_find_all — exhaustive text search over symbol bodies and doc comments (fts)
weave_pin_note, weave_recall_notes — symbol notes (notes)
weave_policy_lint — boundary rules (policy-lint)
weave_search_semantic — experimental, mock embeddings (vector)

Developer Workflows

Multi-repo linking, notes on symbols, PR blast radius, contract checks, a pre-flight check for agent edits, a local pre-push hook, and the file watcher. 

# Feature: federation (in the team bundle). Index both repos first.

# Compose two repo graphs; also runs Tarjan SCC cycle detection and records contract hashes
weave link ../backend-service ../api-gateway

# Query the linked graph across the repo boundary
weave query-federated ../backend-service ../api-gateway "callers(AuthService.verifyToken)"

# One .canvas architecture map spanning both repos
weave report-federated ../backend-service ../api-gateway --out architecture.canvas

# Every consumer file and line that must change before a symbol is removed
weave plan-migration AuthService.verifyToken
# Feature: notes (build with --features team,notes)

# Pin a note to a symbol; expires after 24 hours by default
weave note pin AuthService.verify "Rate-limited per RFC 6238 section 3; do not remove jitter."

# --keep: never expires, and is flagged stale when the symbol's content changes
weave note pin --keep --kind arch_decision PaymentQueue "Single-writer by design, see ADR-014."

# List notes and their status
weave note list

# Notes reattach to their symbol across reindexes. If the symbol is deleted,
# the note is marked [orphaned]. Agents read them via weave_recall_notes.
# What does this branch's diff touch? (three-dot merge-base against --base, no network)
weave blast --base main

# Markdown (default) written to a file, ready for gh pr comment
weave blast --base origin/main --format md --out pr-blast.md

# JSON for scripts
weave blast --base origin/main --format json

# Hops and direction: --depth N (default 2, or all), --direction callers|callees|both
weave blast --base origin/main --depth all --direction both

# Waive the check; --reason is required and recorded in the output
weave blast --base origin/main --skip --reason "Docs-only change"
# Feature: federation. Compare exported-API contract hashes against linked repos.
# Exit code follows [federation] staleness_policy: strict | warn | ignore
weave check-contracts

# Show added / removed / changed symbols when drift is found
weave check-contracts --diff

# Fail only on provider symbols this repo actually imports
weave check-contracts --diff --scoped

# Report drift but always exit 0
weave check-contracts --warn-only

# Waive drift for all linked repos or one peer (--reason required)
weave check-contracts --allow-drift-for api-gateway --reason "Coordinated release"

# Check registered Git submodules instead of linked repos
weave check-contracts --submodules

# Pre-flight check for agent edits: phantom symbols, submodule encapsulation
# violations, stale submodule references
weave verify
weave verify --file src/auth.rs --range 100:180 --format json
weave verify --submodules
# Install a local, offline pre-push hook (no Cargo feature needed)
weave hooks install

# The hook runs:
#   weave blast --base <base> || true     (advisory, never blocks the push)
#   weave check-contracts --submodules     (no-op when no submodules are registered)

# --base defaults to origin/HEAD, else local main/master
weave hooks install --base origin/main

# Replace an existing pre-push hook that weave did not create
weave hooks install --force

# Remove it (only removes a hook weave installed)
weave hooks uninstall
# Feature: watch (build with --features team,watch)

# Foreground watcher: debounce edits, then reindex incrementally
weave index --watch

# Large edits (more than [watch] blast_radius_ceiling symbols affected) are
# deferred behind a marker shown by weave status instead of reindexing.

# To run the watcher inside weave serve --mcp, set it in config:
weave config set watch.enabled true

Graph Hub & Snapshot Sync (weave sync)

When managing large codebases across teams, compile with --features hub to synchronize pre-indexed graph snapshots via your central hub registry. Pull instant snapshots in CI or local environments without re-indexing from scratch, and publish verified post-merge snapshots. 

# 1. Hydrate the pre-computed graph snapshot for the current commit
weave sync pull

# 2. Fall back to the hub's latest default-branch snapshot if current commit isn't indexed yet
weave sync pull --fallback-latest

# Writes atomically via a .rebuild swap, so a crash mid-pull can't corrupt the database
# Publish current graph snapshot to the hub (typically executed in CI post-merge)
weave sync push

# Enforces safety invariants:
# - Refuses to push from dirty or non-default feature branches
# - Validates base_commit_sha against hub head (returns 409 conflict on mismatch)
# - Triggers automatic atomic rebuild on the hub disk spool queue
# Point repository to your internal hub registry (via CLI or .weave/config.toml)
weave config set hub.url "http://hub.internal.corp:8080"
weave config set hub.snapshot_retention 10

# In .weave/config.toml:
# [hub]
# url = "http://hub.internal.corp:8080"
# snapshot_retention = 10
# Launch the standalone weave-registry daemon on a central server/container
weave-registry \
  --bind 0.0.0.0:8080 \
  --data-dir /var/weave-hub/data \
  --max-queue-depth-per-repo 50 \
  --max-pushes-per-minute-per-repo 10 \
  --max-snapshot-bytes 50000000 \
  --auth-token "$WEAVE_REGISTRY_TOKEN"

# One worker thread per repository drains pushes sequentially, no lock contention
Snapshot Signature Verification (hub-provenance)

Enable --features hub-provenance to require hex-encoded HMAC-SHA-256 signatures (X-Weave-Signature), keyed by an operator-held secret of at least 32 bytes, on every snapshot. Modified or corrupt snapshot blobs are rejected before hydration; without a key file, verification is disabled.

Query Commands Cheat Sheet

You can run graph queries directly from your shell or let agent tools invoke them automatically:

weave query "callers(X)"

Every inbound call site referencing a given function, method, or struct.

weave query "callees(X)"

Every symbol called directly from inside a target definition.

weave query "impact(X)"

Transitive dependents of a symbol: the blast radius of changing it.

weave query "path(A,B)"

Shortest call path connecting two symbols in the graph.

weave query "latency(X)"

Latency annotations on a symbol from imported OTel traces (feature: otel).

weave search <query>

Full-text search over symbol names, signatures, bodies, and doc comments (add --semantic for the experimental vector search, feature: vector).

All four graph queries take the same filters: path:, lang:, kind:, visibility:, edge:, e.g. weave query "callers(X) lang:rust visibility:public".

Configuration Guide (.weave/config.toml)

All runtime behaviors in Weave Graph are controlled deterministically through .weave/config.toml or via CLI commands like weave config set <key> <value>. 

# .weave/config.toml — Complete Annotated Reference

# Workspace mode: "single" repository or "multiple" (federated workspace)
mode = "single"

# Database Storage Location (optional relocation off repo tree)
[storage]
home = "/fast/nvme/weave-cache"     # Keeps git repos clean; zero dirty artifacts

# Federation & Cross-Repository Linking (--features federation)
[federation]
linked_repos = [
  "../auth-service",
  "../payment-service",
  "../inventory-service"
]

# File Watcher & Incremental Auto-Sync (--features watch)
[watch]
enabled = true                     # Auto-reindex on file save
debounce_ms = 2000                 # Burst event debounce window
blast_radius_ceiling = 200         # Defers reindex if blast radius exceeds 200 symbols

# Visualization & Reporting (--features viz)
[report]
format = "all"                     # "canvas", "markdown", "html", or "all"
auto_open = false                  # Open browser automatically after weave report

[viz]
mode = "static"                    # "static" offline HTML or "server"
port = 8080                        # Loopback port (127.0.0.1 only)

# Centralized Registry Sync (--features hub)
[hub]
url = "http://127.0.0.1:8080"      # Endpoint of weave-registry daemon

# Role-Based Access Control Masking (--features rbac)
[rbac.users]
alice = ["internal", "core"]       # Unmasks private functions matching role
bob = ["public_api"]

# Local SLM Intent Router (--features slm)
[slm]
default_model = "qwen2.5-coder-0.5b"
backend = "llama-cli"              # "llama-cli" or "heuristic"
lazy_load = true                   # 0MB idle RSS until weave ask is run

CLI Configuration Commands

weave config set <k> <v>

Sets scalar or dotted configuration keys in .weave/config.toml.

weave config get <k>

Reads and prints the current value of any dotted key.

weave link <repo_a> [repo_b]

Links two repositories, adding each to the other's [federation] linked_repos (feature: federation).
